# 政务新闻聚合与解读平台 · 需求文档 v1.0

> 更新时间：2026-11-04
> 状态：需求确认稿（待技术方案设计）

---

## 1. 产品定位

**一句话**：聚焦广东省政务新闻的结构化收集、AI 解读与政策趋势分析平台。

- **内容来源**：广东省各级政府官方发布（政府官网、部委/厅局网站）
- **核心价值**：不只是「收集」，而是通过 AI 从海量新闻中提炼高质量信息，辅助判断政策走向
- **访问范围**：仅本人使用（单用户），暂不公开，无需备案
- **演进路径**：网站（一期）→ 小程序/公众号（二期，复用同一套 API）

## 2. 内容来源规划

### 2.1 源清单（广东省）

| 层级 | 来源 | 预估日增量 |
|---|---|---|
| 省级 | 广东省政府门户网站、省政府新闻办 | 数百条 |
| 省直部门 | 发改委、工信厅、商务厅、科技厅、住建厅、财政厅、卫健委等重点厅局官网 | 数百条 |
| 地市级 | 广州、深圳、珠海、佛山、东莞等 21 个地级市政府官网及政务发布 | 数千条 |
| 重点区县（可选二期） | 经济强区县政务网 | 视需要 |

### 2.2 源站点管理

每个来源登记为一条「源站点」记录：

- 名称、URL、地域（省/市两级）、机构层级（省/市/区县）
- 抓取方式（RSS / HTML 列表页 / 接口）、抓取频率、启用状态
- 支持随时增删源，不改代码

## 3. 内容数据模型

一条新闻 = 结构化记录，字段分五组：

### 3.1 基础字段
| 字段 | 说明 |
|---|---|
| 标题 | 抓取页标题 |
| 原文 | 全文（存纯文本 + 原始 HTML），**不可修改**，保证可信度 |
| 原文链接 | 官方 URL |
| 发布时间 | 官方标注的发布时间 |
| 抓取时间 | 入库时间 |

### 3.2 来源字段
| 字段 | 说明 |
|---|---|
| 源站点 | 关联源站点表 |
| 地域 | 省 → 市（两级字典，预留区县级） |
| 机构层级 | 省级 / 市级 / 区县级 |

### 3.3 分类字段
| 字段 | 说明 |
|---|---|
| 内容类型 | 新闻动态 / 通知公告 / 政策文件 / 政策解读 / 招采公示 / 征求意见 等（字典表） |
| 主题标签 | 经济、科技、民生、房地产、教育、医疗、营商环境…（字典表，一条新闻可多标签） |

### 3.4 解读字段（AI 生成）
| 字段 | 说明 |
|---|---|
| 摘要 | 1-3 句话摘要 |
| 核心要点 | 结构化要点（政策对象、关键措施、时间节点、涉及金额等） |
| AI 解读 | 影响分析、与既往政策的关联 |
| 置信度/质量分 | AI 自评 + 规则校验，低分进入待复核队列 |
| 复核状态 | 自动通过 / 待人工复核 / 已复核 |

### 3.5 系统字段
- **唯一指纹**：URL 归一化哈希 + 标题指纹 + 正文 SimHash（去重用）
- **状态**：已抓取 → 已解读 → 已发布 / 跳过（重复）/ 失败

## 4. 更新与去重机制

### 4.1 更新策略
- **定时任务**：每日至少 1 次全量抓取（频率可配置，重点源可提频到每小时）
- **手动触发**：后台「立即更新」按钮，异步执行并显示进度

### 4.2 去重规则（三层漏斗）
1. **URL 精确匹配**：归一化 URL（去参数、统一协议）后哈希比对
2. **标题相似度**：同一源站点内，标题相似度 > 阈值（如 90%）视为重复
3. **正文指纹**：SimHash 汉明距离 ≤ 3 视为近似重复（应对转载、改标题）

- 重复新闻：标记「跳过」，不录入；若正文有实质更新，记录版本变化并更新原文
- 抓取失败的源：记录失败原因，连续失败自动告警

## 5. AI 解读流水线

由于日增几千条，解读必须是**批处理流水线**而非逐条实时：

```
抓取入库 → 预处理（正文抽取、清洗）→ 去重过滤
        → AI 批量解读（摘要 + 要点 + 分析）
        → 质量校验（低分进入复核队列）
        → 入库发布
```

- **批处理**：按源/批次分组，控制并发与成本
- **成本控制**：短新闻用轻量模型，重点新闻（政策文件类）用强模型；摘要与全文解读分级生成
- **质量兜底**：AI 置信度低的条目标记「待复核」，后台人工抽查
- **原文不可改**：AI 只写解读字段，原文与官方永远一致

## 6. 政策走向分析（进阶模块，二期）

在积累数据的基础上，提供：

1. **主题热度追踪**：某主题（如「旧改」「专精特新」）的时间线与各地市动向
2. **政策信号聚合**：征求意见稿 → 正式文件 → 落地通知的全链路串联
3. **地市对比**：同一主题下 21 个地市的政策力度与进度对比
4. **周期性报告**：每周/每月 AI 汇总报告，提炼趋势判断

> 依赖：一期需保证字段完整（时间、地域、主题标签），分析模块才有抓手。

## 7. 网站功能

### 7.1 一期最小可用（MVP）
- **首页**：新闻流（时间倒序），卡片显示标题/来源/地域/标签/摘要
- **筛选器**：地域（省/市）、内容类型、主题标签、时间范围、关键词搜索
- **详情页**：原文展示（附原文链接）+ AI 摘要 + 核心要点 + AI 解读
- **简单位后台**（仅本人）：
  - 手动触发更新、查看抓取进度与失败日志
  - 源站点管理（增删改、启停）
  - 待复核解读队列处理

### 7.2 登录
- 单用户，简单口令/密码登录即可（不开放注册）

## 8. 架构扩展性设计

| 扩展点 | 设计 |
|---|---|
| 抓取与网站解耦 | 抓取器为独立模块/定时任务，产出统一格式入库；换源、加源不改网站 |
| 消息队列 | 日增几千条，抓取与解读走队列 + 多 worker，可横向扩容 |
| 字典表驱动 | 内容类型、主题、地域均为字典表，加维度零代码改动 |
| API 层 | 前后端分离，小程序/公众号直接消费同一套 API |
| AI 模块可替换 | 解读模型、提示词独立配置，换模型不影响数据结构 |
| 多端预留 | 数据模型与 API 不绑定 Web，二期小程序直接复用 |

## 9. 分期路线

| 阶段 | 内容 | 里程碑 |
|---|---|---|
| **一期** | 网站 + 定时抓取 + 三层去重 + AI 解读流水线 + 筛选浏览 + 简单后台 | 每天自动更新广东全省新闻，可搜索可筛选 |
| **1.5** | 抓取源扩容至 21 地市全覆盖、解读质量调优、复核工作流 | 日均稳定数千条入库 |
| **二期** | 小程序/公众号（复用 API）、政策走向分析模块、周期报告 | 多端访问 + 趋势判断能力 |

## 10. 明确不做（一期）

- ❌ 公开访问、注册、多用户
- ❌ 政务新媒体（公众号文章）抓取——反爬复杂，二期评估
- ❌ 区县级全域覆盖——仅收录重点区县
- ❌ 全文检索引擎（如 ES）——数据量初期用数据库全文索引即可，量级上来再升级
